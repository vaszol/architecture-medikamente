# Классификация данных

## Схема слоёв хранилища

### СЛОЙ 1: RAW ZONE (сырые данные + теги)
- Хранение оригинальных данных (но с тегами конфиденциальности)
- Теги: PII_HIGH, MEDICAL, FINANCE, ANONYMIZED, RETENTION_DAYS
- Доступ: только Data Classification Engine и Data Steward
- Шифрование: AES-256

### СЛОЙ 2: ANONYMIZED ZONE (обезличенные данные)
- PII заменены на токены / хэши
- Медицинские данные: k-anonymity (k≥5)
- Доступ: аналитики, BI-инструменты, ML-инженеры
- Шифрование: AES-256

### СЛОЙ 3: AGGREGATED ZONE (агрегированные данные)
- Только агрегаты (суммы, средние, распределения)
- Нет возможности деанонимизации
- Доступ: любой сотрудник с BI-доступом
- Шифрование: стандартное

### СЛОЙ 4: ANALYTICS ZONE (витрины данных)
- Готовые датасеты для BI (Power BI, Superset)
- Готовые датасеты для ML (обучение моделей)
- Только обезличенные данные
- Доступ: по RBAC (роли: analyst, ml_engineer, executive)

## Дополнительные меры защиты

| Мера                    | Описание                                            | Реализация                    |
|-------------------------|-----------------------------------------------------|-------------------------------|
| Column-level security   | Разные права на разные колонки                      | PostgreSQL RLS, Apache Ranger |
| Data masking            | Маскирование чувствительных полей при просмотре     | Dynamic data masking          |
| Row-level security      | Пользователь видит только свои строки               | PostgreSQL RLS                |
| Audit logging           | Логирование всех запросов к хранилищу               | Audit Store + SIEM            |
| Data retention policies | Автоматическое удаление данных после срока хранения | Политики S3 Lifecycle         |
| Purpose limitation      | Данные помечаются целью использования               | Метаданные purpose            |

## Метрики эффективности классификации данных
### Технические метрики

| Метрика               | Формула               | Целевое значение | Как помогает оптимизации                            |
|-----------------------|-----------------------|------------------|-----------------------------------------------------|
| Precision (точность)  | TP / (TP + FP)        | > 95%            | Уменьшает ложные срабатывания (over-classification) |
| Recall (полнота)      | TP / (TP + FN)        | > 98%            | Уменьшает пропуски PII (under-classification)       |
| F1-score              | 2 * (P * R) / (P + R) | > 96%            | Баланс между точностью и полнотой                   |
| False Positive Rate   | FP / (FP + TN)        | < 1%             | Снижает излишнее обезличивание                      |
| Processing Time       | время на 1 запись     | < 100 мс         | SLA для real-time классификации                     |
| Throughput            | записей/секунду       | > 10 000         | Масштабируемость                                    | 

### Бизнес-метрики

| Метрика               | Описание                                              | Целевое значение |
|-----------------------|-------------------------------------------------------|------------------|
| PII Leak Prevention   | Количество утечек PII через аналитику                 | 0                |
| Compliance Score      | % соответствия 152-ФЗ                                 | 100%             |
| Data Utility          | % данных, доступных для аналитики после обезличивания | > 85%            |
| False Positive Impact | % ложных срабатываний, повлиявших на бизнес-решения   | < 0.5%           |

## Масштабируемость системы
### Стратегии масштабирования

| Компонент       | Текущая мощность   | План роста          | Стратегия масштабирования                                       |
|-----------------|--------------------|---------------------|-----------------------------------------------------------------|
| Ingestion Layer | 10 000 записей/сек | 100 000 записей/сек | Горизонтальное масштабирование Kafka partitions + Spark workers |
| PII Detection   | 1 000 записей/сек  | 10 000 записей/сек  | GPU-ускорение (NVIDIA T4), батчинг                              |
| Classification  | 10 000 записей/сек | 50 000 записей/сек  | Шардирование по типам данных                                    |
| Raw Zone        | 10 TB              | 100 TB              | S3 + автоматическое tiering (Standard → Glacier)                |
| Anonymized Zone | 5 TB               | 50 TB               | Columnar format (Parquet) + компрессия                          |
| Analytics Zone  | 1 TB               | 10 TB               | Materialized views, кэширование                                 |

### Автоматическое масштабирование (Auto-scaling)

| Триггер                      | Действие                      | Задержка      |
|------------------------------|-------------------------------|---------------|
| CPU > 70% на 5 мин           | +1 ingestion worker           | 2 мин         |
| Kafka lag > 10 000 сообщений | +2 PII detection workers      | 3 мин         |
| Запросов в час > 100 000     | +1 query node                 | 5 мин         |
| S3 запросов > 1000/сек       | Включить кэширование (Redis)  | 1 мин         |
| Ночь (00:00-06:00)           | Уменьшить workers до минимума | по расписанию |
