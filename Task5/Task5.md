# Разработка cutover-плана

## Анализ текущей ситуации (As-Is)

| Характеристика       | Текущее состояние (As-Is)                                |
|----------------------|----------------------------------------------------------|
| Архитектура          | Монолит + файловый сервер + 1С в файловом режиме         |
| Хранение данных      | Excel, JPG, PDF на общем диске (неструктурированное)     |
| Бизнес-критичность   | 24/7 приём пациентов, остановка недопустима              |
| Интеграции           | ККМ → OLE/TCP (устаревший протокол), лаборатория → файлы |
| Безопасность         | Отсутствует (нет шифрования, аудита, RBAC)               |
| Квалификация команды | Есть бизнес-аналитик и администратор, но нет DevOps      |

## Сравнение стратегий миграции

| Критерий	                     | High-level design	         | Parallel run	                | Branch by abstraction   |
|-------------------------------|----------------------------|------------------------------|-------------------------|
| Downtime                      | Высокая (полная остановка) | Низкая (постепенный перевод) | Очень низкая (пошагово) |
| Сложность                     | Средняя                    | Высокая (синхронизация)      | Высокая (абстракции)    |
| Риск потери данных            | Высокий                    | Низкий                       | Низкий                  |
| Требуемые ресурсы             | 1 команда                  | 2 команды (старая + новая)   | 1 команда + рефакторинг |
| Время миграции                | 2-3 недели                 | 3-4 месяца                   | 4-6 месяцев             |
| Подходит для 24/7             | ❌ Нет                      | ✅ Да                         | ✅ Да                    |
| Подходит для legacy (1С, OLE) | ❌ Нет                      | ✅ Да (параллельно)           | 🟡 Частично             |

## Обоснование выбора: Parallel run
### Почему Parallel run?
1. Медицинская клиника работает 24/7 — остановка системы недопустима
2. Высокая критичность данных — потеря медкарт или записей недопустима
3. Legacy интеграции (ККМ через OLE, лаборатория через файлы) требуют параллельной работы
4. Постепенное обучение персонала — сотрудники осваивают новую систему без стресса
5. Возможность отката — при проблемах работаем на старой системе

### Преимущества Parallel run для «Медикаменте»:
- Нулевой downtime (клиенты не замечают перехода)
- Возможность верификации данных (сверка старой и новой системы)
- Обучение персонала в процессе
- Постепенное отключение legacy компонентов

### Ограничения и их mitigation:
- Двойная нагрузка на IT (поддержка двух систем) → наём временных инженеров
- Синхронизация данных → CDC (Change Data Capture) инструменты
- Дополнительные расходы → бюджет миграции

### План отката (Rollback)

| Ситуация                     | Действие                                               | Время  | Ответственный        |
|------------------------------|--------------------------------------------------------|--------|----------------------|
| Ошибка в Patient Portal      | Отключаем портал, пациенты записываются через ресепшен | 15 мин | DevOps               |
| Рассинхронизация данных > 1% | Останавливаем CDC, сверяем вручную, перезапускаем      | 4 часа | Бизнес-аналитик      |
| Сбой 1С клиент-сервер        | Возврат на файловый режим (бэкап)                      | 2 часа | Администратор 1С     |
| Утечка PII                   | Полная остановка миграции, аудит, уведомление DPO      | 1 час  | Технический директор |
| Критический сбой (>4 часа)   | Полный откат на старую систему                         | 4 часа | Вся команда          |

### Критерии успеха миграции

| Метрика                     | Целевое значение | Метод проверки           |
|-----------------------------|------------------|--------------------------|
| Потеря данных               | 0%               | Сверка чек-сумм до/после |
| Downtime для клиентов       | 0 часов          | Логи API Gateway         |
| Время отклика новой системы | < 200 мс         | Prometheus               |
| Ошибки при миграции         | < 0.1%           | Логи ETL                 |
| Обучение персонала          | 100%             | Тестирование             |
| Утечек PII                  | 0                | DLP + аудит              |
